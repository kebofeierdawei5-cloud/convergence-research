# 000906cons / CSI800 Scope Audit — 2026-10-07

Status: **DIAGNOSTIC / NO SEMANTIC CHANGE**

## 1. Audit question

Determine whether the historical `000906cons.xls` dependency is:
1. part of the original IIOS product requirement;
2. necessary for the current M1.2 cross-sectional research proposal;
3. being elevated beyond its justified scope; and
4. consistent with the engineering constitution.

## 2. Finding

### Original IIOS product requirement

The original product is a **candidate-driven, single-company investment decision system**. The user performs coarse industry/company screening first; IIOS performs deep analysis, valuation, forecast, decision, position, monitoring and validation for the selected company.

The original requirement explicitly states that the system is **not a full-market screening system**.

Therefore:

```text
000906cons / CSI800 membership
≠
original Investment Core input
```

It is not required for the core company-level decision chain.

### Later M1.2 research requirement

FM04/FM05 showed insufficient state-conditioned selection support when the exploratory epoch used only CATL.

The controlled successor design chose **cross-sectional universe expansion with threshold preservation**. In that design, a PIT security universe is required to add security-level observations without weakening the frozen minimum common-inner-observation threshold.

For that specific research objective:

```text
historical universe membership
→ origin universe construction
→ cross-sectional backtest
```

is a legitimate methodological requirement.

`000906cons.xls` is being used as a candidate source for the historical CSI800 membership component of that universe. CSI officially identifies index code 000906 as CSI 800 and states that CSI 800 is a 800-stock broad-market size index with semiannual sample adjustment. This makes historical membership snapshots materially relevant when the research design uses CSI800 as its outer universe. 

## 3. Why the exact historical file matters

The purpose is **not** to feed the investment decision model with an index file.

The purpose is to answer, for each historical forecast origin:

> Which securities were actually in the declared research universe at that historical point?

The historical membership boundary is needed to avoid silently using today's constituents for yesterday's research.

Using the current `000906cons.xls` for historical origins would create a survivorship / universe-look-ahead problem.

The exact historical bytes also provide a reproducible source anchor for the declared universe, rather than letting a later reconstructed list become the normative source.

## 4. Requirements-deviation assessment

### Assessment: **PARTIAL DEVIATION RISK**

It is **not** a deviation if:

- A02 remains a separate Research Track capability;
- CSI800 is explicitly justified as the frozen universe choice of a new research epoch;
- A02 does not gate the Investment Core / MVP company-analysis product;
- the research epoch is separately scoped, frozen and owner-approved;
- alternative admissible universes remain possible in future epochs if methodologically justified.

It **is** a deviation if:

- A02/CSI800 becomes a general product dependency for single-company analysis;
- inability to recover `000906cons.xls` is treated as inability to run the core IIOS investment workflow;
- the project implicitly changes from candidate-driven research to full-market screening without a separate scope decision;
- the historical CSI800 choice becomes permanent merely because the current research design happened to choose it.

## 5. Principle-compliance assessment

Current implementation is substantially consistent with the core engineering principles:

- no current snapshot is promoted to historical evidence;
- exact-byte matching is required for the historical target;
- checksums without bytes are rejected;
- `retrieved_at` is not treated as `known_at`;
- free-first is preserved;
- paid vendor data is not mandatory;
- independent preflight is separated from collection;
- missing B evidence fails closed.

Therefore there is **no identified evidence-governance principle violation in the current implementation**.

The main risk is **scope inflation**, not evidence-policy failure.

## 6. Recommended governance interpretation

The correct architecture boundary should be:

```text
IIOS Investment Core
    |
    +-- user-selected company
    |     → company PIT evidence
    |     → analysis / valuation / forecast
    |     → decision / position / monitoring
    |
    +-- Research Track (optional capability)
          → historical cross-sectional universe
          → CSI800 / another explicitly frozen universe
          → conditional forecast research
```

Therefore `000906cons.xls` should be classified as:

```text
RESEARCH-TRACK / HISTORICAL-UNIVERSE-EVIDENCE
```

not:

```text
INVESTMENT-CORE / UNIVERSAL SYSTEM DEPENDENCY
```

## 7. Current project consequence

Do **not** infer from this audit that the current A02 work should simply be deleted.

The current M1.2 successor proposal genuinely uses cross-sectional expansion to address FM05's insufficiency finding. For that proposal, a valid PIT universe is required.

However, the project should stop describing CSI800/A02 as though it were an original IIOS product requirement.

The right statement is:

> CSI800 historical membership is a methodological input to one proposed cross-sectional research epoch, not a foundational requirement of the original IIOS investment decision system.

## 8. Decision

```text
000906cons necessity for Investment Core = NO
000906cons necessity for proposed cross-sectional M1.2 epoch = YES, conditional
scope-creep risk = REAL
principle violation = NOT FOUND
recommended classification = RESEARCH-TRACK ONLY
```

No code behavior, A02 admission rule, or research-epoch semantic is changed by this audit.
