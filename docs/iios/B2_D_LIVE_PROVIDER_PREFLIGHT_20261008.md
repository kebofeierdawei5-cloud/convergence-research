# IIOS B2-D — Live Provider Adapter / Replay Preflight

Date: 2026-10-08
Status: **BLOCKED — LIVE PROVIDER CREDENTIAL / RUNTIME NOT SUPPLIED**

## What is implemented

B2-D now has a provider-neutral runtime boundary:

`configured provider`
→ HTTPS invocation
→ raw response bytes
→ request/response SHA-256
→ deterministic replay record.

The runtime configuration requires:

- HTTPS provider endpoint;
- API key;
- model identifier;
- 32-byte runtime Ed25519 private key for the adapter's signed runtime attestation;
- bounded timeout.

Configuration is fail-closed when any required secret/configuration is absent or malformed.

## Important authority distinction

The adapter can authenticate the **runtime adapter** with its signing key. It does not, by itself, cryptographically prove that the model response was generated by the claimed provider.

Provider identity remains governed by the B2-C trust registration. A production deployment therefore must bind:
- actual provider endpoint/API credential;
- registered provider_id/version/policy;
- runtime signing key;
- replay receipt;
- the semantic artifact admission receipt.

## Required release evidence

To close the live B2-D gate, one authorized run must contain:
- real request;
- real provider response;
- request/response hashes;
- provider runtime attestation;
- independently verifiable replay record;
- B2-C signed/admitted semantic artifact;
- end-to-end natural-language lineage;
- no Decision/approval/execution bypass.

No fixture may satisfy this release gate.
