# IIOS 本地投资分析：最简启动指南

## 只记住一个入口

更新仓库到最新 main 后，在仓库根目录**双击 `启动IIOS投资分析.command`**。

首次运行若 macOS 阻止打开，可在 Finder 中右键该文件并选择“打开”。需要 Python 3.10 或更新版本；无需安装 Python 包、配置 API key 或安装本地模型。

## 启动后怎么做

1. 按提示填写公司名称、股票代码、市场、分析截止日、当前持仓和人工核实价格。价格必须大于 0；股价来源默认注明“用户手动输入、未独立核验”，可按实际情况补充。A 股代码可输入 `SZ002810`、`002810.SZ` 或 `002810`；`SH600000`、`BJ430047` 也会自动规范化。港股可输入 `HK00700` 或 `00700.HK`。
2. **截止口径选项不再要求普通用户自己写时区：** `1` = 严格日期级截止（截止日 00:00+08:00，价格观察日必须早于截止日）；`2` = 截止日收盘后（默认且推荐，自动设置为截止日 15:30+08:00，允许使用同日收盘价）；`3` = 自定义时点（高级选项，需输入如 `2026-10-12T15:30:00+08:00` 的完整时点。常规收盘后分析直接回车接受默认 `2`。价格观察日默认按截止口径推荐：模式 1 默认上一个工作日，模式 2 默认截止日（若落在周末则回退到最近的工作日）。程序会拒绝周六/周日作为收盘价观察日期；仍需人工确认交易所节假日，因为当前不自动查询交易日历。价格时间默认按收盘价 15:00+08:00 处理，普通收盘价直接接受默认即可；只有日内/非收盘报价才选择自定义时间并输入实际时间。来源说明自动标记为“人工输入、未独立核验”，不再要求另手工填写。
3. 向导会打开 ChatGPT 和一个专用响应 JSON 文件，并把**完整研究提示 + 本次 JSON 模板**放入剪贴板。你只需在 ChatGPT 粘贴并发送提示；无需另外上传模板，也无需先手动找齐公告文件。提示会要求 ChatGPT 主动检索截止时点前可访问的公司公告、财报、交易所及监管来源，并在 evidence_register 中登记可打开的 URL、发布时间/已知时点与事实摘要。请确保当前 ChatGPT 会话支持联网检索；如无法访问某份来源，就标记未知，不能编造。
4. ChatGPT 返回完整 JSON 后，将它复制到程序自动打开的 `pilot-chatgpt-response-标的代码-时间戳.json` 文件里并保存（macOS TextEdit 使用 Command+S）。新版会自动检测保存后的文件更新（大小、修改时间和内容 SHA-256），通常约 1 秒内开始读取和校验，不需要再按回车；即使修复后的 JSON 长度与旧文件相同也能检测；如果终端仍显示等待，可确认保存成功，或按一次回车立即检查。程序会先对照可信的本地输入模板恢复 ChatGPT 改写或遗漏的人工控制字段（终端显示恢复清单；原始响应文件不被改写，恢复记录随本次私有输入保存），再校验研究内容和数值情景。其他完整性或逻辑校验若未通过，仍会阻止分析。若未通过，程序会把包含缺项反馈、原始模板和上一份回答的修复提示复制到剪贴板；切回 ChatGPT 粘贴发送，再把新的完整 JSON 覆盖保存到同一个响应文件。系统会自动检测新版本并重试。无需手工修改 JSON 字段，也不必重填标的。等待期间可按 Control-C 退出。
5. 日期级与时间点合同有明确区别：模式 1 的价格观察日必须严格早于截止日；模式 2/3 的观察日可以等于截止日，但价格可获得时点必须不晚于截止时点。周末观察日期会被拒绝；如需同日收盘价，选择模式 2 即可，不要只输入一个日期充当时间戳。时间边界不匹配时，程序会阻止该价格进入回报计算，不会偷偷改日期或伪造时点。结构化 `price_input.price` 是唯一计算用价；备注若明确写了另一个当前价/手动报价，系统会标记冲突并强制 `REVIEW_REQUIRED`。Bear/Base/Bull 的期末总财富需满足 Bear ≤ Base ≤ Bull；独立论点失效压力测试不参与概率加权，必须量化且比 Bear 更悲观，否则不能认为投资论点通过。被引用来源若缺少 `known_at`、时间戳无效，或只有与截止日相同的日期而没有具体时刻，将标记为时间未知/精度不足，并强制输出 `REVIEW_REQUIRED`，不会让它们悄悄支撑 BUY/ADD。显式时间点和时间检查只用于个人试运行，不证明来源真实性、原始数据完整性或使用权，也不改变 `PILOT_NON_CANONICAL` 状态.

**入场价与成交/分红资格必须分开理解。** 本地价格输入是观测/参考价，不是券商成交回报。为回答“如果能以这个价格买入，预期回报如何”，系统把收益、目标入场价及日期化分红计算标为“假设截止日按输入参考价买入”的反事实测算；报告/JSON 会明确标记实际成交未确认、不保证按该价成交，也不代表实际分红权益已取得。现金分配只有在截止日前的官方来源、税前/税额/税后算术、市场日期顺序及“假设入场时具备资格”均通过时才进入该反事实回报；仍有资格或日期歧义时保持 UNKNOWN 并阻断回报，不可把“可以按输入价成交”或“已获得分红”当成事实。Replay/验收 ZIP 必须保留并校验这组假设字段。

**不要把完整 JSON 粘贴到终端。** 整个流程只需在 ChatGPT 粘贴研究提示，再把完整回答复制进专用 JSON 文件。模板文件仍作为本地审计副本保存在 `~/.iios-private/local-pilot/inputs/`，但无需上传给 ChatGPT。

## 如何理解新增的决策策略预演

本地试运行会调用 IIOS 现有 Decision Kernel 评估行动优先级，但这仍然只是 `PILOT_NON_CANONICAL` 预演，不创建正式 Decision。

报告现在把两件事分开显示：

- **价格层独立筛选**：使用当前人工输入价格和现有确定性回报/入场价计算，显示 `PRICE_SCREEN_PASS`、`PRICE_SCREEN_FAIL` 或 `PRICE_SCREEN_UNRESOLVED`。
- **核心决策策略预演**：依据 Trust、论点、风险、回报以及缺失的决策条件，显示策略内核的行动和首要原因。

即使价格层筛选通过，当前向导仍未收集正式 Thesis Admission、组合容量/仓位约束状态和完整 BUY/ADD 仓位包。因此总体试运行行动可能仍为 `REVIEW_REQUIRED`。这是有意保留的决策门槛，不表示价格计算失败，也不能靠把状态手动改成 PASS 来绕过。非正式 AI 输入即使触发 BUY/ADD/EXIT/REDUCE，也会被降级为人工复核。

## 经营驱动因素树与独立预测桥（B4）

研究提示要求 ChatGPT 除每股估值情景外，另给出 operating_driver_forecast：按产品/业务线分别记录年产能、实际产量、实际销量、实际净售价、单位变动成本，并为 Bear/Base/Bull 提供情景驱动。每一数字必须标记为 OBSERVED_ACTUAL、ISSUER_FORECAST、ANALYST_ASSUMPTION 或 UNKNOWN；事实/公司预测要指向已登记来源，否则不会被用于计算。未知要留空并解释缺口。

经营桥严格按“销量 × 净售价”计算收入、按“销量 × 单位变动成本”计算直接变动成本，再单独处理现金固定运营费用、折旧、融资成本、税、资本开支与营运资金变化。收入/产量不是实际售价；计划产能也不是实际销量。模型会显示各个 Bear/Base/Bull 经营结果、来源问题和缺失驱动。

该层先量化经营场景，不会自动把项目净利润当作公司 EPS，也不擅自覆盖现有每股估值。如果增量需求与既有业务替代、项目归属税后利润、可转债稀释股数等桥接未成立，就保留每股价值传导为 NOT_LINKED_TO_PER_SHARE_VALUE；后续 B5 再完成估值映射。所有结果仍是 PILOT_NON_CANONICAL，不是正式预测准入或投资授权。

百龙创园案例特别区分国内功能糖干燥扩产项目与泰国工厂，并把设计产能、发行人爬坡计划与真实产销分开。7,800/10,400/13,000 吨等申报数字不能直接写成已实现销量/利润；项目第 3/4/5 年与自然年计划的映射存在待核口径时，必须保留 RAMP_CALENDAR_BASIS_UNRECONCILED，直到正式投产日、月度生产、实际销量/净售价/单位成本和转固/营运资金资料足以对齐。
## 组合风险预算与条件仓位包（建议完成）

完成 ChatGPT 研究 JSON 并通过验证后，向导默认进入组合信息填写，避免直接回车就跳过关键决策上下文。确实暂时不填写时，需明确输入 `0`；跳过后组合约束仍为 `UNKNOWN`，系统不生成条件仓位。组合信息由操作者提供，不交给 AI 推定；只保存在本机私有目录，不上传 GitHub，也不会授予实际交易权限。

选择填写时，先明确组合约束是否确实通过。只有选择 `PASS` 才继续输入；随后依次输入：是否允许新增该标的风险敞口、论点失效压力情景下允许损失的组合净资产百分比、操作者自定入场区间、初始/目标/最大单股仓位。仓位和损失预算均按组合净资产百分比填写，例如 `1` 表示 1% NAV。不得把“可投资产”与“最大容忍损失”混为一谈。

程序使用独立的 `thesis_break_stress` 期末每股财富，按入场区间上沿计算压力损失率，再以“组合风险预算 ÷ 单股压力损失率”得到风险预算隐含仓位上限，并与操作者给出的单股集中度上限取较低者。此结果是**条件测算**而不是目标仓位命令；如果当前价格不在区间内、压力测试未通过、风险证据缺失/时点未知、组合合同结构检查失败或预期回报门槛不通过，就不会给出条件新增仓位。若已有持仓超过推导上限，只提示人工复核，不自动减仓。

另需区分两类风险上限：输入模板中的 `decision_parameters.max_loss_pct=25` 是当前试运行的 Bear 情景损失率上限，用于回报筛选及 B6 风险价格上限；它不是组合净资产损失预算，也不是回撤保证。模板中的 `decision_parameters.required_return_annualized=0.15` 是默认 Required Return；如某只股票应采用更高门槛（例如 20%），请在把模板发送给 ChatGPT 前，先在本地模板中改好该值。程序会要求 ChatGPT 返回时原样保留这两个字段，不能由模型自行把 Bear 损失上限从 25 改成 50/90，或把 20% 回报要求改回 15%；若响应改动或漏掉任一字段，系统拒绝该响应。该保护针对向导模式，直接运行本地 JSON 时，操作者仍应自己复核这两个 `decision_parameters` 字段。

即使报告显示 `CONDITIONAL_PACKAGE_READY_NOT_AUTHORIZED`，实际获准新增仓位仍为 `0%`。这个本地试运行不会创建正式 Decision，也不替代正式风险/证据/Thesis Admission、人工审批或交易执行权限。风险/组合合同结构验证 PASS 不等于证据正式准入，也不保证投资模型有效。

## 输出在哪里

输入和结果仅保存在本机私有目录：

- 输入模板与 AI 完成的输入：`~/.iios-private/local-pilot/inputs/`
- 分析结果：`~/.iios-private/local-pilot/runs/`

每次分析会生成中文 `report.md`、机器可读 `analysis.json`、本地运行记录 `pilot_receipt.json` 和输入副本。报告运行后自动打开。

## 重要边界

该路径复用 IIOS 既有标的、期限与确定性回报/入场价计算，目标是尽快完成真实个人使用测试。但它仍是 **PILOT_NON_CANONICAL**：

- 人工价格、来源摘要、AI 研究评估和情景假设并未自动完成正式 Evidence/PIT、Forecast 或 Valuation Admission。
- 试运行建议不是正式 IIOS Decision，也不等于 canonical `IIOS_RUN_RECEIPT`。
- MIE、证据和关键模块存在未知项时，报告应显示 `REVIEW_REQUIRED`，不应该用内部估值替代不可识别的市场隐含预期。
- 报告会单独列出结构化证据 ID、是否存在对应来源登记记录，以及未解析的 ID；存在来源登记不等于正式证据准入。被引用来源的 `known_at` 未知、无效或时间精度不足会阻止 BUY/ADD。为避免 Markdown 阅读器兼容问题，情景、假设和来源信息以标准标题和列表呈现，不依赖 Markdown 表格.
- 人工最终审批仍必需；不会自动下单或执行交易。

首轮只需跑出一份真实标的报告。后续优先修复实际运行暴露的问题，不让额外的防篡改工作阻塞使用。


## 估值传导与入场价联动（B5）

ChatGPT 会分别返回 B4 的经营情景和 `valuation_transmission` 结构。完成响应验证后，本地向导会再让操作者独立确认主估值模型类别，以及 EPS 倍数模型中的每股估值锚/终值是否已经包含该项目。这个选择保存在本机输入中，不由 AI 代选。

本批只有 EPS / 市盈率倍数模型支持项目增量传导。系统按项目税后净利润、所有权比例、被替代存量业务的税后归属利润、基础股数、可转债潜在新增股数、其他稀释股数和 P/E 倍数计算增量每股价值，并以完全稀释口径传导到 Bear/Base/Bull 以及 Base 入场估值锚。随后仍由原有 15% 回报/安全边际/风险价格上限求解器计算目标入场价。

操作者确认原估值已经包含项目时，系统只展示敏感性而不叠加；若原估值是否包含项目不确定，或 B4 预测期间、模型类别、项目归属、存量业务蚕食、可转债稀释与必要输入不完整，则保留原有每股估值，不做部分传导。DCF、DDM、SOTP、RNPV 暂不套用 EPS 倍数公式，须在后续独立建模后才能传导。论点失效压力测试不自动增加项目价值。

B5 仍属于 `PILOT_NON_CANONICAL`，不会创建正式估值准入、正式 Decision 或交易授权。仓库 CI 通过不替代新的 macOS 实际运行。

## 主 EPS 来源与稀释股数勾稽（B27）

当操作者选择 EPS_MULTIPLE 时，每个 Bear/Base/Bull 情景除了填写声明 EPS 与 P/E，还必须提交 `earnings_bridge`。程序会在本地要求以下链条同口径闭合：

`预测期间一致的上市公司股东归属净利润 ÷ 加权平均稀释股数 = 复算 EPS`

如果 B4 的经营预测是 **COMPANY_WIDE**，且对应情景的财务输出被标记为可用于决策，EPS 桥必须引用该公司整体净利润，扣除有明确依据的归属调整（例如非控股股东损益），并将计算结果与声明的归属净利润核对。如果 B4 只有 **PROJECT_INCREMENTAL** 项目增量，项目利润不能当成整家公司净利润；此时必须另行提供一个明确标记的公司整体归属净利润基准，项目增量仍由 B5 的独立传导路径处理。

程序也会核对盈利期间、项目是否已包含在估值基准、股数是否为加权平均稀释口径，以及复算 EPS 与声明 EPS 的差异。任一关键字段缺失、期间不一致、归属净利润对账失败、EPS 超过容差或项目包含状态与操作者确认冲突时，主 EPS_MULTIPLE 估值、预期回报、目标入场价和 B6 价格敏感性必须保持未知/阻断。分析假设可以保留，但必须显式标注为假设；算术可复算不代表预测事实已核实，也不代表正式估值准入。
