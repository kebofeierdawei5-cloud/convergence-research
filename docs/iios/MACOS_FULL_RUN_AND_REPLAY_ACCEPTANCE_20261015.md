# IIOS：真实 Mac 全流程运行与 Replay 验收指引（2026-10-15）

## 本次目标

本次只验收当前 canonical main 上的本地投资试运行：完成一次新的真实公司分析，检查首次运行包，再用程序保存的原始 input.json 进行 Replay 重算，并检查 Replay 包。它不扩展投资模型、不另造计算链，也不授予正式决策或交易权限。

验收入口会编排仓库已有的本地 pilot CLI：
- 首次运行：现有研究向导；
- 运行包检查：现有只读 SHA-256/字节数校验；
- Replay：现有原始输入校验、重新计算与决策材料字段比较；
- 最后对 Replay 输出包再做一次哈希检查。

**只有你自己的 Mac 完成实际运行并产出私有文件包后，才能完成 Mac 验收。Linux/GitHub CI 仅验证代码与测试，不代替真实 Mac 验收。**

## 一、运行前准备与首次启用

### 第一次启用“自动更新本机代码”

需要说明一个引导限制：已经在本机的旧版启动脚本不可能自动获得自己尚未包含的更新代码。因此，如果你本机已有的「验收IIOS全流程与Replay.command」尚不包含“安全更新 origin/main”逻辑，必须先完成这一次性引导更新；从那以后，每次双击新版本都会先自动更新本机仓库，再启动验收。

如果你的仓库目录仍是 `$HOME/projects/convergence-research`，在终端**单独执行下面这一行**，先检查本地修改：

```bash
git -C "$HOME/projects/convergence-research" status --short
```

- 如果命令有输出，先保留并自行提交/备份这些本地修改；不要继续 pull，也不要删除文件。
- 如果没有输出，再单独执行这一行：

```bash
git -C "$HOME/projects/convergence-research" pull --ff-only origin main
```

如果你的仓库路径不同，只替换路径部分。若该命令失败或报告分叉，停止并保留完整错误；不要运行 `git reset --hard`。完成这一次更新后，确认仓库根目录已有「验收IIOS全流程与Replay.command」和 `tools/iios_update_local_main_v01.sh`。

### 后续每次运行都会自动更新

1. 在 Finder 中双击仓库根目录的「验收IIOS全流程与Replay.command」。
2. 启动器会先确认这是 Git 仓库、配置了 `origin` 且工作区干净，随后获取 `origin/main` 并验证本机代码版本。
3. 如果本机 `main` 落后，脚本只执行 `git merge --ff-only origin/main`；如果在干净的其他分支上启动，它会切换到 `main`，并保留原分支指针。
4. 如果存在未提交/未跟踪文件、分支分叉、本机独有提交、网络故障或更新后版本校验失败，脚本会停止，不启动投资分析；它不会自动 stash、reset、强制覆盖或删除本机文件。处理完成后重新双击即可。
5. 更新成功后，程序才检查并启动与当前 main 对应的 Python 模块。

Mac 需要 Python 3.10 或更新版本。无需安装本地大模型、无需配置付费 API key，也无需登录 GitHub CLI。研究阶段仍由你在浏览器中使用 ChatGPT 完成。不要删除历史运行目录；脚本不需要清理旧文件。

## 二、建议首次完整运行：只双击一个文件

在 Finder 中，双击仓库根目录的 **「验收IIOS全流程与Replay.command」**。

如果 macOS 首次阻止打开，在 Finder 对这个文件点右键，选择「打开」，按系统提示确认。不要把多行脚本粘贴到 zsh，也不要在仓库外执行该文件。

启动菜单：

- **1 — 新建分析并完成全流程 + Replay（推荐）**：先运行原有 IIOS 向导；向导完成后自动校验首次运行包、进行 Replay、检查 Replay 包。
- **2 — 选择已有首次运行并进行校验 + Replay**：不重新做 ChatGPT 研究，适合之前已经生成报告但还没有 Replay 验收的运行包。
- **3 — 只校验运行包**：只检查已存在运行包的文件、结构和哈希，不做 Replay。不能据此宣称 Replay 通过。
- **0 — 退出**：不新增分析，也不删除或改写已有运行包。

第一次完整验收请选择 1。脚本会显示各阶段结果；结束时会保留终端窗口，按回车前可以查看或复制失败原因。完整的启动/运行日志保存在本机私有目录中。

## 三、向导输入：请按真实事实填写

向导会要求你输入公司、代码、市场、分析截止日、截止口径、当前持仓、你核实的价格、该价格观察日和可获得时点。请逐项确认：

- **价格是你本次核实的真实价格**，不是随意沿用旧输入。2026-10-09 的历史收盘价格不能当作 2026-10-15 的当前价。若你分析的是当日收盘后，应明确选择向导中的“收盘后分析”口径，并按真实交易日填写价格观察日期。
- 价格来源会保持“操作者手动输入、未独立核验”类别。不要把手动报价说成交易所原始数据已验证。
- 按实际截止日期做 PIT 分析。如当天并非交易日，不要仅因为向导提供默认值就假定当天有收盘价；需确认真实观察日。当前程序不自动判断所有交易所节假日。
- 向导打开 ChatGPT 后，把剪贴板中的完整研究提示粘贴进 ChatGPT 并发送。提示已带本次输入模板，无需另外把私有价格文件上传 GitHub。
- ChatGPT 返回完整 JSON 后，复制完整 JSON，粘贴进向导打开的专用 TextEdit 响应文件，按 Command+S 保存。**不要把 JSON 粘贴进终端。**
- 回到终端按回车，向导会校验响应。如果校验未通过，先读屏幕上显示的缺项/不符合原因。程序会尽量将修复提示复制到剪贴板；切回同一 ChatGPT 对话粘贴发送，把新的完整 JSON 覆盖到原响应文件、保存，再回终端按回车。不要因为 JSON 校验失败就重新填写标的或删除文件，也不要手改模型字段来强行绕过校验。

### 组合与仓位上下文（必须如实回答）

研究 JSON 校验通过后，向导会询问组合约束、是否允许增加风险、可承受的论点失效损失、操作者考虑的入场区间，以及初始/目标/最大单股仓位。

本次以“完成全流程输入”为目标，应完成这些输入。只有在你确实没有可靠的组合数据时，才选择 UNKNOWN/BLOCKED 或明确跳过；不要为了让验收变绿而虚构 PASS。真实未知应继续显示 UNKNOWN，验收脚本会如实报告尚未完成的输入项。

百分比按组合净资产比例填写，例如 1 表示净资产的 1%；风险预算不是可投资资金总额，也不是目标收益率。必须满足：
初始仓位 ≤ 目标仓位 ≤ 最大单股仓位。
入场区间下沿不得高于上沿。程序只给出条件测算，不产生实际获准新增仓位，也不会下单。

### B5 主估值模型与项目基准口径（必须如实回答）

向导随后要求你**作为操作者**确认主估值模型，不能让 AI 替你选：

- 如果你的主模型确实是 EPS/市盈率倍数模型，选 EPS_MULTIPLE 后还要回答：原有每股终值/估值锚是否已经包含该项目的价值。
  - 已包含：明确选“已包含”，不能重复叠加；
  - 明确不包含：只有在项目归属利润、被替代存量利润、股数和稀释等输入完整时，才可能进行 B5 传导；
  - 不知道：保留 UNKNOWN，不要为了通过验收猜一个答案。
- 如果主模型是 DCF/FCF、DDM、SOTP、RNPV 或其他模型，应选择实际使用的模型。当前 B5 只有 EPS_MULTIPLE 适配器可调整每股情景，不会把其他模型硬塞进 EPS 公式。
- 选 UNKNOWN 或无法确认 EPS 模型的项目包含口径时，B5 不应叠加价值。验收脚本会把它列为“完整输入尚未通过”，即便基础分析或 Replay 技术校验成功，也不会宣称完成了包含这些输入的全流程验收。

## 四、自动进行的验收步骤

在向导生成首次运行后，脚本会依次执行：

1. **首次运行包哈希校验**：通过现有 CLI 检查 input.json、analysis.json、report.md 的 SHA-256 和字节数，必须与首次运行的 pilot_receipt.json 一致。
2. **首次运行包结构校验**：核对运行 ID、输入/报告文件是否存在且非空、当前分析 Schema、B5 估值传导字段、B6 价格区间/约束敏感性字段，以及正式决策和交易执行权限均为 false。
3. **Replay 重算**：以已校验首次运行目录中的原始 input.json 为输入，调用现有 --replay-run 入口。不是简单复制旧报告，也不是将两个新生成 ID 直接比较。
4. **决策材料比较**：要求 Replay 状态为 PILOT_REPLAY_MATCHED，比较状态为 MATCH，hash_verification 为 PASS，并且 mismatched_fields 为空。运行 ID/生成时间等易变身份字段不作为决策材料一致性目标。
5. **Replay 包校验**：检查 Replay 自己的 input.json、analysis.json、report.md 与其 pilot_receipt.json 的哈希和字节数，同时核对它的 replay_of 确实指向首次运行的 pilot_id。
6. **权限和不下单边界**：检查运行目录私有权限、输出文件权限，并确认 formal_decision_created、canonical_run_receipt_created、execution_authorized、auto_execution 均为 false。
7. **输入完整性提示**：确认组合输入包已提供，并检查操作者的 B5 模型选择；EPS_MULTIPLE 还需明确项目是否已被基准估值包含。UNKNOWN 不会被自动升格为 PASS。

完整成功的结束语会明确显示首次运行目录、Replay 目录、关键文件位置和 MATCH 结果。若技术 Replay 匹配但组合或 B5 信息仍被跳过，脚本会以“完整输入验收未通过”结束；这是防止把半完成运行误判为验收通过，不是要求你伪造未知事实。

## 五、自动验收结束后，还要人工看四类内容

在报告中打开首次运行的 report.md，另用 Finder 打开同目录的 analysis.json 和 pilot_receipt.json。到 Replay 目录中再看对应三个文件。首次与 Replay 的目录不同，文件名相同。

重点复核：

1. **标的与价格时点**：公司、代码、币种、分析截止日、人工输入价格、观察日期和 known_at 是否都准确；价格 assurance 是否明确为操作者输入且未独立核验。
2. **研究结论与回报/价格**：看 decision.provisional_action、return_metrics、15%年化目标、目标入场价/价格上限及 B6 的 90%/100%/110%敏感性。价格筛选不能单独把总体行动提升为 BUY/ADD；若估值、回报或风险数据不充分，应当保留 UNKNOWN / REVIEW_REQUIRED。
3. **B4/B5/B6**：检查经营驱动因素是否区分实际值、发行人预测、分析师假设和 UNKNOWN；B5 是否真正满足传导条件，或合理地显示 NOT_LINKED；B6 是否解释绑定的入场价约束、价格位置和敏感性。
4. **组合、风险与权限**：组合仓位包、论点失效压力测试、主要风险、论点失效条件和重新评估触发条件是否符合原始回答；报告和 JSON 的 provisional action 是否一致；正式决策、实际新增仓位授权、交易执行均未被假定为已授权。

检查首次与 Replay 的 pilot_receipt.json 中 replay_comparison：应看到 MATCH、hash_verification PASS、空的 mismatched_fields，并且 prior_pilot_id 指向首次运行。报告内容本身若存在逻辑问题，不能因为 Replay MATCH 就视为投资逻辑通过；Replay 只证明当前代码对同一输入得到相同决策材料。

## 六、文件在哪里、怎么反馈失败

所有输入、完成后的 JSON、运行输出和验收日志应留在本机：

- 输入与完成后的输入：~/.iios-private/local-pilot/inputs/
- 每次首次分析和 Replay 输出：~/.iios-private/local-pilot/runs/<pilot_id>/
- 验收日志：~/.iios-private/local-pilot/acceptance-logs/

正常一次完整成功会留下一个首次运行目录和一个 Replay 目录。脚本不会自动清理它们，不会上传 GitHub，也不会把个人价格和组合数据提交到仓库。请不要把含私有价格、完整输入或组合细节的文件提交到 GitHub。

若失败：

1. 不要删除运行目录，不要修改 input.json / analysis.json / report.md / pilot_receipt.json 后再声称原包通过。
2. 记录终端中的完整错误行、退出码和提示的 acceptance-logs 文件路径。
3. 若失败发生在首次研究回答校验阶段，按生成的修复提示继续当前向导。
4. 若失败发生在哈希校验或 Replay 阶段，保留首次和 Replay 目录。重新双击脚本后可选择菜单 2，针对指定的首次运行包再次执行校验与 Replay，不需要重新调用 ChatGPT 研究。
5. 将错误输出和对应日志发回。不要执行 git reset、手动删目录、调整权限后冒充原结果，亦不要靠放宽校验条件处理不匹配。

## 验收定义

**技术验收通过**需要首次运行包哈希通过、Replay 重算 MATCH、Replay 输出包哈希通过、关键字段/权限/不交易边界符合要求。

**完整输入验收通过**还要求操作者提供组合上下文并确认 B5 主估值模型；若主模型是 EPS_MULTIPLE，必须回答原基准是否已包含项目。数据或投资事实仍 UNKNOWN 时可以如实保留，不可虚构 PASS。

无论脚本最终是否 PASS，本地研究仍为 **PILOT_NON_CANONICAL**。它不是正式 IIOS Decision，不是买入批准，不产生实际授权新仓位，也不执行交易。只有在真实 Mac 上运行并复核实际文件包后，才能把本轮“Mac 全流程 + Replay”记录为完结；在此之前，不进入 B7 功能扩展。
